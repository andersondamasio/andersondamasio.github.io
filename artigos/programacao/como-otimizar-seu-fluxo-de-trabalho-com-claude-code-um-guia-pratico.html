Claude Code: instalação, conta e permissões na primeira sessão

Responsável pelo site: Anderson Damasio. Conteúdo produzido com apoio de IA. Critérios editoriais.

Publicado em: 13/12/2025 10:29

Atualização editorial em 10/10/2026: instalação, acesso e limites corrigidos com documentação; a data da publicação original foi preservada.

Instalar o Claude Code, autenticar uma conta e autorizar acesso ao projeto são etapas diferentes. Este guia organiza essas decisões para uma primeira sessão local. A versão anterior apresentava uma instalação pessoal não comprovada e tratava a conexão com o GitHub como obrigatória; essas afirmações foram removidas.

1. Escolha a instalação para o seu ambiente

A documentação de instalação apresenta opções para Windows, macOS e Linux. No Windows, uma alternativa é winget install Anthropic.ClaudeCode. Depois de instalar, abra outro terminal e confira claude --version. O comando claude doctor oferece diagnóstico de instalação e configuração. Se o executável não for encontrado, confira o PATH antes de repetir instalações. Quem usa WinGet precisa cuidar das atualizações pelo gerenciador; não presuma que todos os métodos atualizam da mesma forma.

Escolha primeiro onde o projeto e suas ferramentas serão executados. Um projeto que depende de ferramentas Linux pode justificar WSL; isso é uma decisão de ambiente, não uma exigência universal. Use os comandos atuais da documentação para a plataforma escolhida.

2. Confira a conta e a forma de cobrança

O fluxo de autenticação documentado permite conta Claude elegível, Console ou configuração de provedor corporativo. A sessão local não exige conectar um repositório do GitHub para instalar e autenticar. Execute claude e siga o fluxo correspondente à sua conta. Dentro da sessão, /status ajuda a identificar a credencial ativa. Uma chave de API configurada pode selecionar uma forma de cobrança diferente da assinatura; confirme isso antes de enviar uma tarefa.

Este guia não fixa preço em reais nem recomenda contratar um plano específico. Verifique elegibilidade, limites e cobrança na conta que será usada. Não cole chaves, tokens ou códigos de login no repositório ou em capturas públicas.

3. Separe contexto do projeto de permissões

Segundo a documentação de permissões, o diretório inicial define o contexto principal de trabalho, mas não é uma garantia de isolamento. É possível adicionar diretórios com /add-dir ou --add-dir. Examine as regras em /permissions e conceda somente o acesso necessário. Não conclua que outro diretório é inacessível apenas porque a sessão começou na pasta do projeto.

O arquivo CLAUDE.md registra orientações do projeto. A documentação de memória e instruções explica que /init analisa o código para propor esse ponto de partida. Revise comandos e convenções antes de aceitar o resultado. Essas instruções orientam o modelo; não substituem controles de acesso. A análise usa a ferramenta de IA e deve respeitar o orçamento e a política de dados da sua conta.

Ficha proposta para a primeira tarefa

Comece com uma alteração pequena em uma cópia de trabalho apropriada, sem dados de produção. Antes e depois da sessão, registre:

  • Objetivo: qual comportamento deve mudar e quais arquivos podem ser alterados.
  • Estado inicial: versão da ferramenta, revisão Git e mudanças locais que já existiam. Não descarte trabalho anterior para obter uma árvore limpa.
  • Acesso: diretórios, ferramentas e conexões externas autorizados para aquela tarefa.
  • Critério de aceite: comando de teste do próprio projeto e resultado esperado antes de pedir a implementação.
  • Revisão: diff final, testes realmente executados, falhas pendentes e consumo informado pela conta.

Se o teste não puder ser executado, registre o impedimento; não substitua a evidência por uma declaração do assistente de que o código funciona. Essa ficha permite distinguir uma instalação concluída de uma mudança de software validada.

O que foi verificado

Revisão documental das páginas oficiais citadas em 10/10/2026. Não houve instalação, login, execução de comandos do Claude Code, chamada paga ou medição de produtividade para este artigo. A ficha é uma proposta não executada. Requisitos e opções podem mudar; confirme a documentação e as regras da sua organização antes de usar código ou dados reais.
