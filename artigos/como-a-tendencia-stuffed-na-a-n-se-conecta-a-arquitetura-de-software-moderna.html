Stuffed-Na(a)N: dados em NaN e o limite da serialização JSON

Responsável pelo site: Anderson Damasio. Conteúdo produzido com apoio de IA. Critérios editoriais.

Publicado em: 26/04/2025 17:13

Atualização editorial em 10/10/2026: interpretação da fonte corrigida; a data da publicação original foi preservada.

Guardar informação em uma representação numérica não equivale a preservar essa informação em todos os formatos de transporte. O projeto Stuffed-Na(a)N ajuda a discutir essa diferença, mas sua proposta foi descrita incorretamente na versão anterior deste artigo.

Codificação, não preenchimento de dados ausentes

O repositório Stuffed-Na(a)N apresenta funções para codificar texto em valores NaN e recuperá-lo. A explicação usa os bits da representação de NaN. Isso não corresponde a imputar valores faltantes em uma base de dados, nem demonstra proteção contra vazamentos. As afirmações de segurança e de integridade da versão anterior foram retiradas.

Uma fronteira concreta: JSON

Na especificação ECMAScript, Number.isNaN não converte o argumento antes de verificá-lo. Já a serialização JSON de um número não finito produz null, quando não há transformação personalizada. Um objeto que antes continha NaN pode, portanto, voltar do JSON contendo null. Os dois valores não significavam necessariamente a mesma coisa para a aplicação.

Exemplo executável de um contrato explícito

Este exemplo próprio modela uma leitura numérica: null significa ausência, um número não finito significa leitura inválida e um número finito significa leitura válida. Strings e outros tipos são rejeitados. É uma escolha didática de contrato, não uma regra universal para sensores ou bancos de dados.

'use strict';
const assert = require('node:assert/strict');

function prepararLeitura(valor) {
  if (valor === null) return { estado: 'ausente', valor: null };
  if (typeof valor !== 'number') throw new TypeError('Esperado numero ou null');
  if (!Number.isFinite(valor)) return { estado: 'invalida', valor: null };
  return { estado: 'valida', valor };
}

assert.equal(Number.isNaN(NaN), true);
assert.equal(Number.isNaN(null), false);
assert.equal(Number.isNaN('NaN'), false);
assert.deepEqual(JSON.parse(JSON.stringify({ valor: NaN })), { valor: null });
assert.deepEqual(prepararLeitura(null), { estado: 'ausente', valor: null });
for (const valor of [NaN, Infinity, -Infinity]) {
  assert.deepEqual(prepararLeitura(valor), { estado: 'invalida', valor: null });
}
for (const valor of [0, 3.5, -2]) {
  assert.deepEqual(prepararLeitura(valor), { estado: 'valida', valor });
}
for (const valor of ['NaN', '2', undefined, {}, true]) {
  assert.throws(() => prepararLeitura(valor), TypeError);
}
const leituras = [null, NaN, 0].map(prepararLeitura);
assert.deepEqual(JSON.parse(JSON.stringify(leituras)), leituras);
console.log('Contrato JSON verificado.');

O arquivo completo do exemplo pode ser executado com node verificar.js, sem instalar pacotes. As asserções conferem a conversão de NaN em null, a distinção dos estados, a rejeição de texto e o transporte do contrato pelo JSON. A saída esperada é Contrato JSON verificado.

Em uma API, produtor e consumidor precisariam concordar com esses estados. Um consumidor que interprete toda ausência de valor como zero continuaria errado mesmo recebendo JSON válido. Antes de alterar um contrato existente, acrescente casos de ausência e de valor inválido aos testes dos dois lados e defina como clientes antigos serão tratados.

Alcance da verificação

O exemplo verifica comportamento de JavaScript e o contrato proposto. Ele não executa a biblioteca Stuffed-Na(a)N, não testa a preservação dos bits de NaN entre motores e não constitui um formato de armazenamento, criptografia ou benchmark. A verificação automatizada também não substitui revisão humana do artigo.
