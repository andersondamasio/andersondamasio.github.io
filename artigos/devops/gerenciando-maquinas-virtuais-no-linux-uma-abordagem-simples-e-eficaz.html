Cockpit para máquinas virtuais: componente, acesso e certificado

Responsável pelo site: Anderson Damasio. Conteúdo produzido com apoio de IA. Critérios editoriais.

Publicado em: 27/01/2026 19:26

Atualização editorial em 10/10/2026: requisitos e conclusões revistos com fontes oficiais. A data da publicação original foi preservada.

Para administrar máquinas virtuais com Cockpit, há três verificações distintas: a disponibilidade do aplicativo de virtualização, as permissões da conta e a confiança na conexão ao painel. Conseguir abrir uma página de login não demonstra que a máquina virtual pode ser administrada com segurança.

O componente de virtualização

O projeto lista cockpit-machines como aplicativo para criar, executar e gerenciar máquinas virtuais. Portanto, é preciso conferir esse componente, além do Cockpit básico. Fonte: aplicativos do Cockpit.

O repositório de cockpit-machines descreve integração com libvirt-dbus para operações e notificações e com virt-install/virt-xml para definições de máquinas. Isso não sustenta tratar uma suposta API REST genérica do painel como contrato de automação. Fonte: tecnologias do cockpit-machines.

Acesso e certificado

O guia de execução orienta acessar https://endereco-da-maquina:9090 e autenticar com a conta do sistema. A mesma página separa instruções de instalação por distribuição. Um comando destinado a uma família de distribuições não é uma instrução universal para Linux. Fonte: execução e instalação do Cockpit.

A documentação de TLS informa que, por padrão, a porta 9090 recebe HTTP e HTTPS, com redirecionamento de HTTP para HTTPS e exceções documentadas. Se não encontrar um certificado, o Cockpit gera um certificado autoassinado. Portanto, não é correto dizer que não existe certificado por padrão. Fonte: uso de SSL/TLS no Cockpit.

Como orientação de implantação, não ignore um aviso de certificado apenas porque ele apareceu na primeira conexão. Confira se está acessando o host esperado e valide o certificado por um canal administrativo confiável. Defina a cadeia de confiança adequada ao ambiente antes de usar credenciais. O aviso também pode indicar nome incorreto, expiração ou um certificado diferente do esperado.

Roteiro antes de usar o painel em produção

Este roteiro é uma proposta de verificação, não uma instalação executada:

  1. Registre distribuição e versão. Confira a origem dos pacotes, as instruções dessa distribuição e a disponibilidade de cockpit-machines. Não copie um comando de instalação apenas porque o sistema usa Linux.
  2. Defina quem acessará o painel e a partir de qual rede. Uma porta administrativa alcançável não deve ser confundida com uma porta que precisa ficar aberta para toda a internet.
  3. Confirme endereço, certificado e conta antes de entrar. Teste as permissões necessárias com uma máquina descartável e dados sem valor operacional, sem atribuir privilégios mais amplos por conveniência.
  4. Confira criação, início, desligamento e acesso ao console dessa máquina de teste. Registre a operação que falhou e a mensagem exata, sem incluir senhas ou dados privados no relato.
  5. Antes de alterar uma VM importante, verifique o procedimento de recuperação e seus dados de entrada. Ter um botão de criar ou iniciar não demonstra que existe backup utilizável.

Para automatizar, escolha uma interface documentada da camada que executará a operação e verifique sua versão, autenticação e comportamento de erro. A interface visual e uma API para automação são contratos diferentes; não deduza um do outro.

O que não foi validado

Não houve instalação de Cockpit, criação de VM, migração de VirtualBox para KVM nem teste de certificado neste ambiente. A revisão documental foi feita por Codex. Foram retirados o relato pessoal de migração, a recomendação de simplesmente aceitar o aviso de segurança e a alegação de uma API REST sem contrato citado. A ficha não atesta segurança, recuperação ou produtividade de uma implantação.
